# /month-start — 月初ワークフロー

毎月 1 日ごろに実行する。前月の締めと、今月の予算づくりを対話で進める。

> 前提: 利用者は非エンジニア。Claude が計算・ファイル作成を代行し、人には「方針の判断」だけ聞く。
> **作業開始前に必ず `data/TARGETS.md` を読んで目標（収入・貯蓄率）を把握する。** データ形式は `README.md`「データ設計」を参照。
> **ファイル書き込み前は必ず内容を提示して承認を得る（自動上書き禁止）。**

## 初動チェック

1. `date` で現在日時を確認 → 前月（締め対象）と今月（予算を組む対象）を確定
2. 利用者に「前月 XXXX-XX の締め + 今月 XXXX-XX の予算づくりを進めます。よいですか？」と確認
3. **`npm run import:csv` を実行** — 家計簿 CSV を `data/inbox/YYYY-MM.csv` に取り込む
4. `data/inbox/{前月}.csv` の存在確認。無ければ「家計簿アプリで前月分の CSV をダウンロードして再実行してください」と案内（前月実績の振り返りはスキップして予算づくりだけ進めることも可）

## ステップ A: 前月の振り返り

`data/months/{前月}.md` が無ければ**スキップ**して Step C へ（初回利用）。

ある場合：

1. `data/months/{前月}.md` と、必要なら `data/inbox/{前月}.csv` を Read
2. 収入実績 / 総支出 / 貯蓄率、目標達成可否、超過カテゴリ・余ったカテゴリ Top3 を算出
3. 結果を提示し、利用者の振り返りコメントを聞く（今月の予算づくりに活かす）

## ステップ B: 前月末残高の記録（`data/balances.json`）

- 利用者に各口座の前月末残高を対話で聞く（家計簿アプリの残高画面を見てもらう）
- 口座名は前月の `accounts` キーがあれば再利用して提示（追加・削除可）
- `history` 配列の末尾に追記（同月エントリがあれば上書き確認）

```json
{
  "history": [
    { "month": "2026-05", "recorded_at": "2026-06-01", "accounts": { "メイン銀行": 800000, "電子マネー": 12000 } }
  ]
}
```

## ステップ B-2: 今月の予定をカレンダーから取得（連携時のみ）

- カレンダー連携があれば、今月の**支出に影響する予定**を取得する
  - 影響あり: 旅行 / 外食 / 美容 / 誕生日 / プレゼント / イベント / 帰省 / 大型買い物
  - routine は無視
- 拾った予定を提示し、対応カテゴリの予算を上振れさせる提案をする（例:「中旬に旅行があるのでイベント費 +30,000」）
- 連携が無ければスキップ（予定があるか口頭で聞いてもよい）

## ステップ C: 今月の予算づくり（`data/months/{今月}.md`）

**前月の予算がある場合**: 前月のカテゴリと金額を提示し、実績との対比で 1 カテゴリずつ「増やす？引き締める？」と提案する。

**初回（前月なし）**:

1. `data/TARGETS.md` の手取り収入と目標貯蓄率を取得
2. 今月の使える予算 = 手取り収入 ×(1 − 目標貯蓄率) を計算して提示（これがカテゴリ予算の合計上限）
3. カテゴリ案を提示して利用者と確定する。迷う場合の叩き台（少数で始めるのが続けるコツ）:
   - 食費 / 日用品 / 交通費 / 健康・医療 / イベント費 / 予備
4. 各カテゴリの月予算を聞きつつ、合計が上限に収まるよう一緒に調整
5. 各カテゴリの**週別配分（w1〜w4）**を立てる（合計は月予算と一致させる）
   - 変動費（食費・日用品等）: w1〜w4 に等分。w4 は 22〜月末で長め（7〜10 日）なので少し多めに
   - 固定費（サブスク・会費等）: 引落週だけに計上（例: 15 日引落なら w3 のみ）
   - 単発予定（旅行・美容予約等）: カレンダーで拾った予定の週に集中配分

### カテゴリ設計の考え方（任意のガイド）

- **カテゴリは増やしすぎない**。境界が曖昧なものや前月実績ゼロのものは統合 / 削除を提案し、発生時は「予備」で吸収する
- **変動が大きい固定費**（電気代など）は平均でなくレンジ上端で見積もる（安全側）
- 年 1 回のサブスク等は該当月に乗せ、メモに「◯月限定」と明記

### プリペイド / 電子マネーのチャージ計算（任意セクション）

毎週プリペイドや電子マネーにチャージして使う運用なら、予算ファイルに「今週いくらチャージすればいいか」の表を入れると便利：

```
今週のチャージ額 = 週予算 − その週の自動引落 − 現在のチャージ残高
```

| 週 | 週予算 | 自動引落 | 必要額 | 週初残高 | 推奨チャージ額 |
| --- | ---: | --- | ---: | ---: | ---: |

- 推奨チャージ額はキリよく少し多めにすると突発出費を吸収できる
- /weekly で前週末残高を入れて翌週分を再計算する

## ステップ D: 達成シミュレーション

- `予測貯蓄率 = 1 − (カテゴリ月予算の合計 / 手取り収入)` を計算
- 目標未達なら「◯◯を XX 円削れば目標達成」を 1〜2 案提示
- 利用者が調整したければ Step C に戻る

## ステップ E: 仕上げ

- 完成した `data/months/{今月}.md` を提示して保存（承認後）
- 「週の締め（7・14・21・月末）に通知が来たら /weekly でチェックしましょう」と次の運用を一言伝える

## 守るべきルール

- ファイル書き込み前に必ず内容提示して承認を得る
- 日本円は整数。`recorded_at` / `updated_at` は ISO 8601（JST `+09:00`）
- カテゴリ名は利用者定義。勝手に追加・改名しない
- `history` に同月エントリがあれば上書き / スキップを必ず確認
