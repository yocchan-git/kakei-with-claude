# /weekly — 週次予実ワークフロー

各週の終わり（7日 / 14日 / 21日 / 月末日）に実行する。直近で締めるべき週（w1〜w4）の予実を確定し、振り返りと次週の予算調整を対話で行う。

> 前提: 利用者は非エンジニア。Claude が集計・計算・ファイル更新を代行し、人には「判断」だけ聞く。
> **作業開始前に必ず `data/TARGETS.md` を読んで目標（収入・貯蓄率）を把握する。** データ形式は `README.md`「データ設計」を参照。
> **ファイル書き込み前は必ず内容を提示して承認を得る（自動上書き禁止）。**

## 初動チェック

1. `date` で現在日時を取得 → 対象月（`YYYY-MM`）と対象週を確定
   - 週番号: `Math.min(Math.ceil(日 / 7), 4)` で `1〜4`（README「週の区切り」準拠）。締めるべき週 = 実行日が属する週
2. **`npm run import:csv` を実行** — `~/Downloads` 等にある家計簿 CSV を `data/inbox/YYYY-MM.csv` に取り込む（同月は上書き）
3. `data/inbox/*.csv` の存在確認。無ければ「家計簿アプリで当月の CSV をダウンロードして、もう一度実行してください」と案内して停止
4. `data/months/{今月}.md` の存在確認。無ければ「先に /month-start で今月の予算を作りましょう」と案内して停止

## ステップ A: 実績の集計

1. `data/inbox/{今月}.csv` を Read（多くの家計簿アプリは月単位 CSV。月内全行が入っている前提）
2. 各行を**日付で週に分類**（1-7→w1, 8-14→w2, 15-21→w3, 22-月末→w4）し、カテゴリ別に振り分ける
   - 振り分け先は `data/months/{今月}.md` の予算カテゴリに合わせる
   - 自明なもの（スーパー → 食費 等）は機械的に振り分けてよい
   - **迷う行は勝手に「予備」に入れず、必ず利用者に「これは何費ですか？」と聞く**
   - 一度確定した店名→カテゴリの対応は同じ月の中では記憶して再利用（同じ質問を繰り返さない）
3. 月累計（month_to_date）と週別（w1〜w4）を集計
4. `data/months/{今月}.md` の「カテゴリ別予実」「週別予実」セクションを作成 / 更新（毎回 CSV から全週を再計算してよい）
   - `updated_at` を ISO 8601（JST `+09:00`）で更新

## ステップ B: 予実の突合

カテゴリごとに以下を計算してテーブルで提示：

| カテゴリ | 月予算 | 月累計 | 使用率 | 当週予算 | 当週累計 | 状態 |

- 月使用率 = 月累計 / 月予算
- 状態の目安: 🟢 余裕（使用率 90% 未満）/ 🟡 注意（90〜100%）/ 🔴 超過（100% 超）
- 締めた週で予算を超えたカテゴリ、逆に余ったカテゴリを洗い出す

## ステップ C: 月末着地の予測

- 当月の支出ペースを残り日数で延長して月末支出を予測する
- `予測貯蓄率 = 1 − (予測月末支出 / 月の手取り収入)` を出し、`data/TARGETS.md` の目標と比べる
- 黒字/赤字の見込みと、目標達成できそうかを一言で伝える

## ステップ D: 振り返り + 次週の調整（コア）

### D-1. 振り返り（締めた週について）

- 締めた週のカテゴリ実績を提示し、「なぜそうなったか」を対話で聞く
  - **一時的な要因か、続く要因か**を区別する（旅行で外食増＝一時的 / サブスク追加＝恒常的）
  - 一時的 → 来週への影響なし。恒常的 → 月予算の見直し候補

### D-2. 次週の調整（次の週が残っている場合）

- **カレンダー連携があれば**、次週の予定を取得して支出影響イベントを拾う
  - 影響あり: 旅行 / 飲み会 / 外食 / 美容 / 誕生日 / プレゼント / イベント / 帰省 / 大型買い物
  - routine（仕事・ジム・食事等）は無視
  - 連携が無ければこのステップはスキップ（利用者に予定を口頭で聞いてもよい）
- 残り週の予算をどう動かすか提案する：
  1. **予定の反映** — 予定がある週のカテゴリ予算を上振れ（例:「来週飲み会なので外食費 +5,000」）
  2. **超過のリカバリ** — 一時的超過なら残り週で取り戻すか確認
  3. **黒字の再配分** — 余った分を他カテゴリへ振り替えるか、貯蓄に上積みするか
  4. **恒常超過のフラグ** — 「来月予算で見直し」を `data/months/{今月}.md` の「メモ」に記録
- 利用者が OK したら `data/months/{今月}.md` の該当週の予算セルを更新

### D-3. 月末週（w4）を締めた場合

- 来週は翌月の w1。今月の予算は直さず、「今月の振り返りメモ」を `data/months/{今月}.md` の「メモ」に残す（/month-start で参照）

## ステップ E: サマリー（任意）

- 利用者が希望すれば、今週のサマリー（月使用率・予測貯蓄率・注意カテゴリ・来週のアクション）を短くまとめて提示する
- 通知に流したい場合は、その文面を `npm run reminder` ではなく口頭確認の上で共有する（自動投稿はしない）

## 守るべきルール

- ファイル書き込み前に必ず内容提示して承認を得る
- カテゴリ分類で迷ったら勝手に分類せず必ず聞く。確定した対応は同月内で再利用
- 来週予算の修正は「利用者が OK と言った場合のみ」
- 日本円は整数。`updated_at` は ISO 8601（JST `+09:00`）
- CSV は毎回 `data/inbox/YYYY-MM.csv` に上書きされる前提。週別は毎回 CSV から再計算（差分集計しない）
